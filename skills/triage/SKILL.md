# Triage

Move issues on the tracker through a small state machine, so tickets captured in the moment can be classified later and acted on once they're understood.

Every comment posted during triage **must** start with:

```
> *This was generated by AI during triage.*
```

## Roles

Two **category** roles: `bug`, `enhancement`. Five **state** roles:

- `needs-triage` — awaiting evaluation
- `needs-info` — waiting on the reporter
- `ready-for-agent` — fully specified, an agent can take it
- `ready-for-human` — needs human implementation
- `wontfix` — will not be actioned

Every triaged issue carries exactly one of each. An unlabeled issue goes to `needs-triage` first; `needs-info` returns to `needs-triage` when the reporter replies. Flag conflicting or unusual transitions and ask before proceeding.

## Show what needs attention

When invoked without a target, query the tracker and present three buckets, oldest first, with counts and a one-line summary each: **unlabeled**, **`needs-triage`**, and **`needs-info` with reporter activity since the last triage notes**. Let the user pick.

## Triage a specific issue

1. **Gather.** Read the full issue (body, comments, labels, dates) and any prior triage notes — don't re-ask resolved questions. Explore the codebase using the glossary; check for **redundancy** — an existing implementation of the requested behavior, searched by domain concept, not the request's wording — and report where you looked.
2. **Recommend.** Give your category and state recommendation with reasoning and a brief codebase summary. Wait for direction.
3. **Verify the claim.** For a bug, reproduce it from the reporter's steps before any grilling. Report: confirmed (with code path), failed, or insufficient detail (a strong `needs-info` signal).
4. **Grill if thin.** If the request needs fleshing out, run the `/grilling` and `/domain-modeling` skills together — sharpening terms and recording decisions as they land.
5. **Apply the outcome:**
   - `ready-for-agent` — post an agent brief ([BRIEF.md](BRIEF.md)).
   - `ready-for-human` — same brief, plus why it can't be delegated.
   - `needs-info` — post triage notes: what's established so far, then specific actionable questions for the reporter (never "please provide more info").
   - `wontfix` — close with a comment: if already implemented, point to where it lives; otherwise a polite explanation of the rejection.

## Quick override

"Move #42 to ready-for-agent" — trust it. Confirm what you're about to do, apply directly, skip grilling. If moving to `ready-for-agent` without a grilling session, ask whether they want a brief written.
